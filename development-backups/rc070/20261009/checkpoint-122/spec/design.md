# Design — targeted bitflags repair of the actual prior lock

## 概述

FR-1/FR-2/FR-3 reuse the mature slot01 guard03/launcher04 closure without repeating its once slot. Slot02 source is separately prepared and byte-leased. The original generated216 lock is the actual initial mutable artifact; F13 original230 native lock is the immutable graph comparator. Initial and comparator identities must never be conflated.

## 技术方案

FR-1 changes only bounded adapter inputs: owned slot path02, explicit actual initial lock SHA/size/provenance, new independent marker/raw/target, and source preparation lease. Protect all vendor193/original F13 manifests, three other product locks, all Rust/SQLx migration code and embedded checksum sources. No callback owner/grant or public credential material is introduced.

FR-2 changes only the phase1 command from generate-lockfile to `update -p bitflags@2.13.0 --precise 2.9.4 --offline` while retaining exact two command-scoped path patches and selected PostgreSQL request. Phase0 is fixed official Cargo --version. Phase2 is exactly the existing offline locked metadata after mature after1 acceptance; no source compiler or build script launch is intended. Preserve inherited whole120s/raw2MiB budget and actual bounded ordinary child process/cleanup semantics. Actual error/cancellation/UNKNOWN close cannot advance phase2.

FR-3 strengthens the old after1 policy to exact full216 node/row/edge parity against original230; it does not create a whitelist exception for bitflags2.13.0. Fixed target2.9.4 must have the original registry checksum/source. Precisely14 original unused RSA/MySQL closure identities may disappear. No dependency additions or arbitrary removals are allowed; only the five named FR-3 edge deletions are admitted. Every other source/checksum/row field is exact, apart from the two provenance-checked owned path patches. Full current generated graph and changed dependency arrays are saved; no hand reconstruction of Cargo output. Original source/manager/tool checks precede every phase and final mandatory cleanup. No sourceguard/new conditional may hide primary exceptions or suppress cancellation. A failed repaired graph is a new terminalFAIL, never a reason to broaden admission. Independent source/startup review and genuine execution are separate from this proposal.

## 官方依据与限度

Official cargo-update documentation says --precise selects a specific version; targeted SPEC updates preserve other locked versions unless necessary. Official generate-lockfile documentation says an existing lock is rebuilt with latest available versions. Both were genuinely fetched HTTP200 and sealed; documentation is not this new command's execution proof. Exact installed Cargo1.98.1/version797e8a9bc identity must still be bound by root. Fresh existing external guard/launcher queries against F13 graph have no matching indexed symbols: UNKNOWN/manualHIGH. The failed mini graph index is retained, not presented as a valid index.

## 对应需求

FR-3: all-row source/checksum/version policy, actual full dependency diff, finalsource/runtime and honest resolver-only status.
