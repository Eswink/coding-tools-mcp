# Requirements

## 功能概述

Finite IO subdesign for the separate NT output native CI manager. Parent design budget seal03 remains unchanged. This does not implement or execute a Windows API, grant any VM/publication authority, or make a generic PInvoke toolkit. The existing native Api/Startup/ProcessInfo/Limits/environment_block definitions remain unchanged; only the exact per-stage IO/Job adapter is considered. Original production Go/Rust/native controls remain byte-exact.

## 需求列表

- FR-1: WHEN an ordinary stage prepares IO THEN each stdout/stderr SHALL use one exclusive first-instance local byte pipe with an OVERLAPPED server read handle, one distinct manual-reset event and one stable OVERLAPPED/buffer holder per issued operation. Actual client write handles and stdin read handle SHALL be the exact three STARTUPINFOEX handle-list entries. Client connection SHALL complete before process creation; connection cancellation/completion follows the same strong-frame rules as a read. Caller handles are retained from acquisition, and inherited flags/exact attribute memory stay valid through the real CreateProcessW call. Pipe names or PID checks do not create an owner grant.
- FR-2: WHEN a read/connection is issued THEN the adapter SHALL distinguish no operation issued, immediate completed, IO_PENDING, actual terminal completion and UNKNOWN. GetOverlappedResult with bWait=False SHALL be the per-operation completion observation, with bounded event/poll waits. ERROR_IO_INCOMPLETE remains pending. No buffer, OVERLAPPED object, event or read handle may be released, reused, closed or consumed while an issued operation is pending/unknown. A completed read is copied once before reuse; byte counts must fit the submitted buffer and cumulative per-channel cap2097152.
- FR-3: WHEN cancellation/timeout/forced family cleanup occurs THEN CancelIoEx SHALL be requested for the exact read/connect OVERLAPPED and the actual result recorded; success or ERROR_NOT_FOUND SHALL not be called completion. Each pending operation SHALL receive its independent bounded GetOverlappedResult completion attempt within the original2s IO budget and2700s total ceiling. Actual terminal cancellation is a failure result even when resources can be released safely. Pending/unknown completion SHALL retain the complete strong frame and reject success, without a second close, discard, live-reader close or extra budget.
- FR-4: WHEN closure/after-checks fail THEN real native retirement, source/runtime checks and receipt attempts SHALL remain independent. Primary errors, cancellation and cleanup errors SHALL preserve exact objects together in BaseExceptionGroup where necessary; ordinary observation cannot replace original failure or swallow cancellation. CloseHandle is attempted only once per actual releasable parent holder; on uncertain/failed close its raw value, buffers, identity and sticky deny remain held until this manager process exits. A known empty Job does not cure an unknown self IO frame.
- FR-5: WHEN controls are admitted THEN genuine Windows current-run ordinary controls SHALL exercise immediate/pending reads, two-channel exact bytes+EOF, a delayed writer, outstanding-read cancellation, descendant-held writer, and real protected-handle close failure in an isolated ordinary child. That child retains its expected unknown fault frame until its own actual process exit; parent admission requires its real assigned Job empty and parent IO/handles known closed. This is a negative-control assertion, not a production unknown-close success or full VM closure. Missing capability, malformed bytes, unexpected cancellation/close success, active descendant or retained parent UNKNOWN SHALL fail before original21 NT methods. POSIX parser/scheduler controls and crosscompile cannot supply the native API result.

## 非功能需求

Parent limits remain exact: overall2700s, ordinary native stage120s, at most20 helper/native stages, per stdout/stderr2097152 bytes, cleanup7/2/2 inside total. No new download, retry or budget expansion. Local pipe and syscall preparation use the same finite stage deadline; this does not promise an atomic hard-real-time bound on every Windows kernel syscall. Disposable trusted-host assumption: host tooling does not connect to/replace the exclusive new pipe or swap fixed source/runtime parents during preparation; no such assumption is publication authority. Dedicated parent implementation has no Python reader threads; actual asynchronous native operation holders replace a generic synchronous PeekNamedPipe shortcut.
