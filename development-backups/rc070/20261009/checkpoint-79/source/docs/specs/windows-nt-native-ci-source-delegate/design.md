# Design

## 概述

This is a concrete external-binding and containment proposal, not an implementation. It closes identified research gaps without silently editing original functions or broadening a source result into native success. Parent design/source-only backup freezes remain immutable with their earlier STOP status.

## 技术方案

FR-1: Prepare a two-entry real attribute list: HANDLE_LIST over retained actual stdin/stdout/stderr and JOB_LIST over exactly the actual unnamed no-breakaway Job. Keep attribute values/list allocation, command/environment buffers and Job strong through real CreateProcessW; flags include suspended and extended startup. Original Api.CreateProcessW binding can receive the extended structure cast to its original Startup base pointer, with the correct extended cb/flags, without editing original source definitions. Successful return and actual process/thread holders plus IsProcessInJob are necessary before resume. Do not redundantly call AssignProcessToJobObject after a JOB_LIST assignment and infer anything from a failed duplicate assignment. Native support/association must be proved on current Windows. No return from the FFI call is not a known failure-before-effect; JOB_LIST gives the actual retained Job containment path for a possibly created child, and that Job remains strongly held through cleanup. This still does not invent a known process handle from uncertain output fields.

FR-2: Every native invocation has a before-call state, stable strong arguments and a return observation. A Python exception during/after call does not prove no native operation started; connect/read/write UNKNOWN retain their exact operation frame. For HANDLE-returning acquisition whose return is unobservable, report an unobserved possible native return rather than fabricate its value; it forbids subsequent dependent child creation. Do not treat asynchronous cancellation as a harmless before-call failure or assume a native return was recorded. Preserve the actual typed cancellation object and mark no-return UNKNOWN; the actual creation-time Job association is the containment path, not fabricated ProcessInfo. This subdesign does not install a new signal handler or claim immunity to arbitrary async failures; any proposed signal interception requires its own entry/default-handler/restore contract and independent controls before code. All observed raw returns/error status remain private evidence. Void cleanup/attribute deletion uncertainty is not a successful release proof. Primary/cancel/cleanup/after-check errors retain exact objects; wholemanager startup remains denied until controls cover these branches.

FR-3: Load the native-verified original guard into a fresh private module identity, verify exact function AST/source hashes and capture its original run_git object. The binding context asserts no prior/concurrent substitution, installs only the finite delegate, invokes original restore/verifier functions, then always restores the captured object; restore errors do not suppress primary/cancel errors. The actual evidence must explicitly state original run_git code was retained but not executed while binding was active. Every original higher-level check still operates on native Git-returned bytes and actual custom index/tree; no precomputed API payloads, hidden-file trick or weaker source reader. Tests must compare each real argv/environment/input vector to original contract, not merely compare source AST.

FR-4: The delegate mirrors original Git env removal of caller GIT_* variables, GIT_CONFIG_NOSYSTEM=1, GIT_CONFIG_GLOBAL=os.devnull, GIT_NO_REPLACE_OBJECTS=1 and original core.autocrlf=false/core.hooksPath=os.devnull/-C prefix. It verifies that the original resolver selects the fenced executable; no PATH mutation/shim. Native stdout/stderr are byte-preserved in private per-call artifacts, return0 yields original stdout bytes and nonzero raises the original-compatible RuntimeError summary while all real raw remains saved. Cancellation/cleanup/after uncertainty propagates typed failure, not a synthesized CompletedProcess or ok receipt. Bound IO owns actual child at creation, refuses premature resume and checks root exit/Job empty/natural/selfIO separately. A320-call and16MiB combined raw counter spans preparation and declared source before/after calls; eachcall also has2MiB/channel. No hidden helper outside the counter. Management root stage limit20 is separate; original source descendants exceed20. Exact source preparation terminal raw/counter and actual300s/after60s/overall2700s identities are required; crossing any bound denies, no timeout retry.

FR-5: Data input uses an exclusive local OVERLAPPED outbound server and actual inherited read client. Connection, writes and output reads share stable operation/error/UNKNOWN rules from IO subdesign. Native WriteFile(true) or GetOverlappedResult terminal success contributes only the checked actual byte count; pending means no input memory reuse. Partial completion resubmits only the remaining bytes after known completion; zero progress rejects. After full delivery, CloseHandle of actual server writer is checked once so child gets real EOF. Cancellation independently retires outstanding operations and child/Job, retains unknown holders and denies. For None input, real NUL read endpoint matches the ordinary root's no-input behavior. ZIP/runtime acquisition/source preparation never borrow this pipe as a production transfer capability.

FR-6: Genuine Win ordinary helper child emits/echoes controlled binary bytes to two channels, actual delayed/pending operations and EOF. Overflow/count controls fail-first locally and then native actual current-run evidence verifies rejection, without launching original Go methods. The original guard local_payload path may be exercised on fresh owned exact source payloads as LOCAL_GUARD_TEST_ONLY; its real nativeGit restore result is not a remote fetch proof and never fakes GITHUB context. Immutable backup remote fetch/show must occur in the real named CI with actual environment and native Git. No native startup before full source/runtime/binding/IO/kernel controls and independent literal review.

## 文件结构

Current delta: these three specification documents only. Prospective finite adapter/bounded_run_git_delegate/binding context/native control source are NOTAUTHORED. Existing production/helper/API bytes and six earlier docs remain unchanged. Public backup is source/spec/mode/hash/safe state only; raw subprocess/native/host/runtime data and objects remain private.
