# Design

## 概述

Bounded source-preserving audit/build preparation. 对应需求：FR-1、FR-2、FR-3。

## 文件结构
`spec/{requirements,design,tasks}.md`; `ACTUAL-AUDIT-TOOL-DB-IDENTITY01.json`; `FRESH-BOUNDARY-IMPACTS01.json`; future root slot03 preparation lease, startup packet, mature guard/launcher adapter, separate audit/build raw paths and final safe metadata. Official crate fixture TLS/key/env bytes remain private; public backup is manifest/spec/source-only projection.

## 技术方案
Root copies exact2033 source and real f1789 lock from resolver02 into a new isolated slot; original F13 native lock remains provenance, never the candidate audit input. Full source/tool/DB/absence lease → independent review → sole audit marker/real audit → mandatory after guards and complete JSON decision → gated separate build marker/real build → mandatory source/runtime/DB final checks and bounded cleanup/receipt. Original primary errors and typed cancellation are retained and not masked by observations. New selected buildscript/linker roles must be resolved and sealed before execution; an incomplete closure is a specific startup STOP.

Audit argv uses the actual existing standalone cargo-audit executable followed by `audit --no-fetch --db <DB> --file <absolute lock> --json`, matching previous real invocation grammar. Build argv uses original package defaults, offline/locked/release/target/message-format/manifest-path plus exact two absolute local patch configs; no `--no-default-features`, package subset, fake compiler or rewritten migration. Minimal command-scoped env includes existing official Cargo/Rustup homes, official RUSTC and bounded two jobs/empty target, with no HOME/globalPATH/system modification.

## Runtime roles
Audit: sealed audit executable, DB Git native index/raw1315, original lock, timeout/prlimit/env and process/log cleanup support. Build: official cargo/rustc and selected rustdoc, toolchain lib/rustlib host+target std and compiler dynamic libraries; actual /usr/bin/cc resolves GCC14, ld resolves ld.bfd, as/ar/pkg-config and GCC cc1/collect2/support runtime when used; C runtime/startup objects/dynamic link dependencies and any selected buildscript tool. No source-only inventory can prove a complete runtime closure: root must bind the roles its exact compiler/command genuinely selects, otherwise STOP. Generated artifacts stay under a new owned target; arbitrary host effects are not granted.

## Limits and errors
Audit60s2MiB and build480s2MiB are independent budgets, not extensions of earlier families. Separate raw stdout/stderr with real bounded writer closure, aggregate cap, original failures, final guard even after cancellation; no truncation or synthetic events. JSON audit findings deny; build event JSON and artifact identities are real bytes. Existing cache may be read under original fenced roles; no fetch/tool install and no silent new config. Safe summaries exclude raw host/process/env/TLS/key material.

## 分阶段启动与捕获边界

对应需求：FR-2、FR-3。Root first prepares audit-only03; compiler is separately reviewed afterward. Existing resolver fsize RLIMIT is not a compiler collector because it limits object/ELF generation. V4 run_owned_git_phase uses realtime selector cap but merged stderr, while exact_build_audit.execute uses separate pipes with no executor-level timeout/cap. Neither original function is changed or claimed sufficient. New finite dual-stream capture must preserve raw stream order, aggregate read-time cap, actual owned child cleanup/allcloses and primary exceptions; overflow retainedprefix is partialFAIL, never complete proof. See DUAL-STREAM-COLLECTOR-READONLY-REUSE-BOUNDARY01.json. No new collector implementation or compiler execution is included in this preparation.
