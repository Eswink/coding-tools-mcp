# 设计文档：MCP异步命令v1

## 概述
对应需求：FR-1 FR-2 FR-3 FR-4 FR-5 FR-6 FR-7 FR-8；NFR-1 NFR-2 NFR-3。

## 技术方案
### 技术选型
沿用Rust/Tokio及普通MCP tools/call。原生Tasks已有不同协议代际，当前不更改initialize协议或假定ChatGPT支持；后续只增加适配器，不重写执行内核。
### 架构设计
submit -> 校验 -> 原子登记request_id/fingerprint/job_id -> 返回queued
后台worker -> call_tool(exec_command, yield_time_ms=0) -> ExecSession -> 监测终态
get/list -> 内存任务表 -> 有界状态/日志；cancel -> 置位 -> worker请求直接子进程终止

## 数据模型
每个ToolContext持有Arc<ExecTaskStore>。worker持有共享sessions和tasks的上下文快照（提交时默认目录已解析）。job_id为服务端UUID；request_id由调用者提供，1至128 UTF-8字节；fingerprint为cmd、规范化workdir和timeout_ms的SHA256。不得以HTTP JSON-RPC id去重，因为它只用于请求响应关联。
记录包含queued/running/cancelling/succeeded/failed/timed_out/cancelled、创建/完成时间、执行预算、退出码、终止原因、取消请求位及有界stdout/stderr。终态保留3600秒；最多4个活动任务和32条保留记录，容量满拒绝且不偷偷清除未过期幂等键。

## API 设计
| 工具 | 输入 | 输出 | 需求 |
|---|---|---|---|
| start_exec_task | cmd,request_id,workdir,timeout_ms,confirm,filesystem_scope,reason | job_id,status,accepted,poll_after_ms | FR-1 FR-2 FR-8 |
| get_exec_task | job_id,stdout_cursor,stderr_cursor,limit | 状态、退出信息、两个独立日志页 | FR-3 FR-4 FR-6 |
| list_exec_tasks | 可选request_id | 最多32条摘要，无命令与日志 | FR-6 FR-7 |
| cancel_exec_task | job_id | cancel_requested,status | FR-5 |
HTTP断线不撤销已登记任务；提交失败/未收到响应应重用同request_id，禁止盲目重交新id。get对同一游标无消费副作用。next_cursor始终是绝对字节偏移；截断/滞后用dropped_bytes显式报告；文本编码声明utf-8-lossy，data_base64保留当前页精确字节，客户端可拼接解码以避免中文被分页边界损坏。

## 设计决策
### 决策1：渐进恢复（FR-6）
当前只承诺服务实例存活期间的HTTP断线恢复，不承诺listener或应用重启可接管原进程。返回recovery_scope=service_instance和restart_recoverable=false。下一阶段使用应用级任务监督器、加密元数据、启动代际/进程身份与interrupted终态；不得仅持久化PID后自动kill或重跑。
### 决策2：取消边界（FR-5）
首轮继承现有直接子进程终止能力，返回cancellation_scope=direct_child；不支持自行daemonize或脱离进程的作业。完整Windows Job Object/Unix进程组管理列入下一阶段。
### 决策3：时限与内存（FR-3 FR-7）
不修改旧exec_command的30秒默认与10分钟上限；新异步提交默认10分钟。任务执行时限与结果保留TTL分别计算。额度保护不等于持久任务队列，不排无限队列。

## 测试策略
逐条验收FR-1至FR-8：真实跨平台短/长命令、重复/并发request_id、冲突、首个响应丢弃后查询、退出非零、超时、取消、默认目录、路径越界、read-only暴露、无原生task能力广告、日志环回与游标、容量与TTL。不以静态schema测试代替真实进程测试。Linux/Windows全目标check、全量cargo test和-D warnings必须最终执行。

## 风险评估
call_tool影响MCP与Actions，图谱评估MEDIUM；直接调用者含两个传输入口。上下文/参数/schema改动LOW。FTS离线不可用但符号影响分析可用；不将空搜索结果当无影响。
系统进程重启、长期无人轮询、脱离父进程任务不在当前恢复保证内。模型不会因后台完成自动获得新的会话执行权，必须显式查询；poll_after_ms仅建议，不承诺无限自动轮询。

## 复核修正
读取器排空超时不再丢弃JoinHandle后默默继续；中止并await，结果output_complete=false。完整保留范围内的字节可从data_base64还原，text仅方便显示。该修正影响既有exec timeout monitor，图谱LOW，必须运行旧回归。
