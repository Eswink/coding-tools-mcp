# Design: bounded publication executor

## 概述
FR-1 through FR-8 implement one execution component around the unchanged pure publication core. Baseline M=5beda478f4d04e7a352d0bbc63e1496ee3bca668, tree8daa22b917f985e00ba4b00cae0d5a6f76651678, ordered parents[b97c469b1bd7ffb9973a65e19b798d2573561d92,1564836a538a28f8e6e2aa1c67491dc56f26f47e]. No live publisher entry becomes available.

## 技术方案
Use Python standard library and existing validated helpers. Executor owns the core Transition, staging and attempted operation IDs. Stage owns exact selection, raw plan/provenance and six retained read handles. GitHub transport owns closed HTTPS methods, parsers and bounded streamed bytes. No general transport API, second state machine, replay or new validation framework is introduced.

## Production admission (FR-1)
GateRequirement.verifier is unimplemented and ReleaseEligibility is blocked-only. Fixed authenticators consult these unchanged facts, while a distinct remote-constraint check rejects the missing existing-tag-only guarantee. GitHub CreateRelease can create a missing tag; pre/post GET checks cannot resolve that race. Both production entry and actual mutation-write path remain blocked without genuine authenticators. No constructor argument, callback, environment variable or JSON boolean enables them. Tests patch only fixed unavailable sources and the verified loopback connection factory, never core, serializers, parsers or archive validation.

## Session and outcomes (FR-2, FR-6)
Call start/advance/request_publish unchanged. Sequence: fence/create/observe; six fence/upload/download checks; observe exact six; pause; explicit request/fresh fence/publish/anonymous verify. At most25 operations in one process; no resume importer. Attempt IDs are recorded immediately before first possible HTTP write after connected TLS and fresh action-scoped owner/cancel/deadline checks. Mutation non-success, malformed/mismatched success, disconnect and timeout after dispatch are sticky unknown; no retry/delete/compensation. Confirmed mutation cleanup failure retains IDs. Read failures use existing core classification. Idle pause close only retires local lifetime and preserves the Await state. Complete required cleanup before final success reaches the core, and never mask primary uncertainty.

## Exact receipts and staging (FR-3, FR-4)
Authenticate the selected successful workflow_dispatch consumer run, exact workflow/source/consume job and sanitized artifact ID/name/digest/size/expiry/run/time. The pinned uploader's least-common search root retains one rc-consumer-receipts-* prefix. Require precisely RC_PROVENANCE.json and rc-asset-plan.json below it, plus at most the matching empty directory; reject flat fallback, links, extras and collisions. Reuse existing ZIP central/local/deflate/name validation; receipt ZIP<=64MiB, <=3members, each JSON<=15,999,999 bytes.
Parse strict original shapes and all bindings/limitations/approval-false fields; preserve raw bytes, including verified_at and plan SHA. Reauthenticate the same FINAL/integration/bundle, invoke unchanged _verify_bundle_bytes, and reobserve identities. Copy four payloads and exact provenance into a new PrivateRoot; reconstruct only sorted SHA256SUMS and require original plan size/hash equality. Six assets exclude the plan itself. Retain own root contexts and six nofollow single-link regular handles; fences verify FD/path/root identity, inventory and hashes. Upload streams these handles, checking actual count/hash. No source paths or consumer closed-root ownership transfer.

## Closed HTTP contract (FR-5)
Fixed repository Eswink/coding-tools-mcp; api.github.com metadata and uploads.github.com asset upload. Construct paths from validated IDs/tags/fixed names. Binary GET allows200 or one HTTPS302 to release-assets.githubusercontent.com:443 without userinfo/fragment; strip credentials/cookies. Metadata redirects reject. Final requests are anonymous throughout. API version2022-11-28; metadata2MiB, response headers32KiB, max100pages*100/10000 IDs, payload<=512MiB, chunks64KiB, exact row size stronger than generic ceiling. Fail on duplicate IDs/names, partial lists or exhausted limits.
CreateDraft sends only tag,draft=true,prerelease=true,make_latest=false,generate_release_notes=false; publish PATCH sends only draft=false,prerelease=true,make_latest=false to the owned ID. No tag or DELETE operation. Same-principal draft visibility must come from the unavailable trusted authenticator, never an empty list.
Stable/latest projection binds the fixed external stable ID and /releases/latest ID (zero only authenticated typed absence), canonical id/tag_name/target_commitish/draft/prerelease/published_at and each tag-ref object type/SHA. Hash sorted compact JSON of {stable,latest}; do not reselect anchors or include mutable counters/title/body. This proves selected identity, not all content immutability. Bounded error codes never include response bodies, credentials or signed URLs.
