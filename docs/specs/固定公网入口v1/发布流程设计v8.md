# 发布流程设计v8

## 范围与状态

目标Windows x64 NSIS本地验收包。用户已将真实公网、Cloudflare/FRPS端到端及ChatGPT授权联调转为本地验收，不再作为构建的前置条件。macOS、自动合并main和代码签名不在本次执行范围。只有发布流水线实际成功、附件回读一致才记为交付完成；此文档不是通过证据。

## 版本与来源

最终源码必须先提交，五个文件六处项目版本必须统一为0.2.3。发布工作流不动态改源码，不移动功能分支；从专用release/本地验收v8分支的不可变SHA检出。每个验证和构建作业采用相同SHA，禁止复用旧版本安装包冒充新版本。

## 附件与恢复

GitHub会规范化部分文件名，原中文附件被规范化成v7.json并发生冲突。保留本地中文名，传输层使用唯一ASCII名称及中文标签，证据以固定时间戳ZIP保留原文件名。

校验安装包字节、版本、静默安装、原生窗口、持续进程、Tauri唯一NSIS标记与来源。上传前后均校验SHA256；所有附件完整后发布。仅恢复同一SHA、同一版本、同一摘要的草稿，拒绝其他来源、未知附件、已发布版本变更和标签移动。发布凭据限发布步骤，禁止认证重定向。公开后不携带凭据独立下载并再次校验。

## 依赖

修复SvelteKit、cookie、nanoid、PostCSS审计条目；明确cookie0.7.2 override，验证兼容序列化和非法字段拒绝。拒绝npm --force建议的破坏性SvelteKit0.x降级。保留依赖审计结果，零已知npm漏洞不等于软件没有未知漏洞，也不代表已完成Cargo全依赖安全审计。

## 可维护性边界

新增发布器与回归测试独立成模块；本轮不继续改写已通过原生ACL重复回归的Rust安全路径。历史长文件整理等技术债不伪称清零。旧v0.2.2失败草稿保留为未发布状态，不覆盖或删除用户其他Release。
