# 凭据存储设计 v6

## 范围与验收

当前20轮授权包含源码整合、安全持久化、Windows可下载Release；真实公网联调由用户本地执行。macOS不自动构建。

## 不变量

- AppData及代理URL/扩展字段一起AES-256-GCM加密；主密钥只存系统凭据库，不进入JSON、环境变量、argv或Git。
- 信封schema_version=2、格式版本1、固定算法；内层应用schema仍为1。旧版有版本保护的应用拒绝外壳，不能覆盖。
- 密钥首次创建在DataStore跨进程锁内，先写系统库再回读确认，后写密文；已有密文缺密钥时绝不生成替代密钥。
- nonce每次保存重新生成；认证失败、未来格式、损坏输入不回退默认配置，不打印密钥或明文。
- 文件提交仍为同目录rename；三方合并仍对解密后的AppData运行。
- 单元测试显式隔离临时数据根与测试KeyStore，不可用环境变量在产品中启用测试替身。原生系统凭据另由Linux/Windows CI实际验证。

## 兼容与边界

首次有效读取旧明文配置时自动原子加密，不改变OAuth签名密钥/clientID/固定URL。管理目录内旧profiles.json、app_settings.json及bak在加载时逐个保护；每个文件独立提交，中断可重试，不删除原件。主密钥跟随系统用户凭据库；仅复制JSON到另一账户或清空系统凭据无法恢复，必须先保留原系统用户备份或重新配置。外部早期应用目录、用户自建备份、磁盘旧块、同步历史不声称已擦除。

## 威胁边界

保护离线拷贝的配置与新备份；不防已获得当前系统账户/管理员权限的恶意进程。UI明确请求查看Secret仍返回所需值，运行中服务在内存使用明文。FRPC运行配置另按最小权限处理；主配置加密不等于子进程内存、运行参数全加密。

## 选择

仅chmod/ACL不能保护被复制的JSON；逐字段Keychain引用会放大跨存储事务并遗漏代理凭据。完整payload加密将变更局限在持久化边界，代价是跨账户恢复必须同时保留系统凭据。

## 原始依据

keyring 3.6.3 Cargo.toml和Entry文档；ring 0.17.14 LessSafeKey文档；本仓库DataStore、migrate和配置锁。依赖锁由GitHub Actions在隔离临时副本运行Cargo metadata生成，未自动改动生产源码。
