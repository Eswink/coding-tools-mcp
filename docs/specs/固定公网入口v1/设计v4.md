# 固定公网入口设计 v4

## 概述

继承实施规格v1，不更改认证边界。设计需求FR-1至FR-12均需证据。当前实现、候选设计、缺证据三者严格分离；本文不是发布批准。

## 技术方案

FR-1、FR-2：workspace/endpoint统一规范origin及FRP路由，frp生成器做TOML转义、连接指纹与域名唯一性。候选routes先verify，路由锁内启动并发布，替换失败根据真实rollback状态恢复或清理。TLS透传/https2http与连接TLS分别配置。

FR-3、FR-4：PublicOrigin按listener启动代际独立，Arc共享同代际；所有认证与metadata读取同一快照。Quick只有活session拥有临时origin，持久化不保存临时来源；Named根地址严格校验。生命周期成功、源站可达、授权成功分别度量。

FR-5：DataStore保留比较基线，三方合并不同字段、拒绝冲突；迁移函数仅pub(super)，错误不包含密钥值。同目录临时文件write/sync/rename，稳定旁路OS锁及进程互斥防合作式并发丢失。损坏原文件不得覆盖。

FR-6：拟采用平台安全存储后端，必须明确Secret Service/Keychain/Credential Manager等平台能力、缺失行为、迁移与回滚。当前代码仍JSON存储，不能以现有keyring_store文件名认定已实现系统钥匙串；本轮不引入未经平台实测的密码学实现。

FR-7：前端分别传入固定配置与运行态origin；仅running/starting的当前有效状态可进入Quick复制区。停止态后端回退清空Quick，Named保留已配置固定根地址。现有两个界面候选未提交，保持阻断。

FR-8：原基线E0603来自跨文件半提交，不把当前已有pub(super)修复记作本轮修复。采用原子多文件提交，Linux/Windows全目标检查、全量测试及库级-D warnings；stdout/stderr经pipefail保存，always收集证据但不改失败状态。

FR-9：实机验收按任务v4证据块执行，记录环境、版本、步骤、HTTP/TLS结果与秘密扫描。无法执行则记blocked，不拿状态fixture替代真实网络。

FR-10：发布必须解析现有tag并把SHA传给后续checkout、核对版本、锁定依赖；构建后摘要和来源manifest随产物上传；构建权限只读，发布job单独授予写权限。macOS手动构建与自动Windows标签流程分离。此处是待实现的对策，不意味着现有release.yml已满足。

FR-11：中文文档为权威来源。只在项目.mcp-probe-kit内部创建随机临时specs/fixed-public-entry-v1目录，将三份原始Buffer分别写为requirements.md/design.md/tasks.md。原版check_spec使用docs_dir指向临时镜像。检查前后重读来源和镜像摘要，防止在检查过程中变化；工具错误、版本不符、缺失结构化报告或passed=false均非零退出。校验报告同时携带来源路径/摘要、工具版本和原始结构化结果。结构通过不勾选任务，不改变发布判定。

FR-12：每輪revision绑定review，未提交文件单独分包。平台拒绝阻断同一写操作，继续独立可执行任务但不绕过。最后converge依据真实待办返回，不预设passed。

## 文件结构

生产涉及src-tauri/src/workspace、tunnel、runtime、commands、auth、mcp、actions、data以及src/lib和workspace页面。原测试保留；新增测试和辅助脚本使用中文v命名。

本规格新增需求v4.md、设计v4.md、任务v4.md；规格兼容脚本为scripts/规格校验v4.mjs及独立回归。协议所需英文文件名只在临时生成目录存在，不创建第二份手工权威规格。脚本只读生产源码，不创建commit、执行发布或改动凭据。
