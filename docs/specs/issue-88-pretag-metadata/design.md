# Design: bounded metadata observations without release authority

## 概述

Corresponding requirements: FR-1, FR-2, FR-3, FR-4, FR-5, FR-6. This design governs the implemented metadata-only library and the reviewed diagnostic entry. Hosted execution remains unverified until exact-source CI evidence is reviewed.

## 技术方案 — architecture

New adapter -> new metadata normalization/collection -> distinct immutable metadata receipt. Read-only imports from existing pure PR97 contracts flow in one direction. No old module imports the collector; no production consumer or release route changes. No shared-helper extraction/refactor.

Reuse unchanged `SourceIdentity`, strict primitives and receipt-only `decode`/`parse_json`/`encode`, `WORKFLOWS`, `GATE_IDS` and exact `INTEGRATION_JOBS`/`FINAL_JOBS` constants. SourceIdentity.version is a supplied expectation, not observed source version. Existing `SelectedRunObservation`/`JobObservation` accept success only and are not used for failed/pending metadata. Do not instantiate PreTagCandidate, InvocationIdentity, PreTagEvidenceReceipt, ArtifactObservation or TrustedProducer. `rc_release_eligibility.evaluate` stays unchanged and is exercised by compatibility tests, not bypassed or passed fabricated candidate facts.

The existing `release_tag_gate.paginate/latest_run/successful_run` and `rc_consumer_snapshot` methods are read-only design references. They cannot be called as a pretag controller: candidate resolution requires an existing tag; successful-run helpers reject pending/failed observations; counted pagination and dictionary-only GET do not handle PR review arrays. New normalization is intentionally narrow, with equivalence tests for the shared successful metadata subset. Do not copy or expand old producer/admission logic.

### Concrete bounded network worker

Use one new collector-owned standalone Python worker launched by the current trusted interpreter with fixed argv `sys.executable -I -S <fixed sibling rc_pretag_metadata_worker.py>`, shell=false, close_fds=true, explicit minimal noncredential environment and stderr discarded. This single reviewed interpreter-child launch is the only process exception. No caller __main__ import, multiprocessing spawn, arbitrary executable/module/path, shell, candidate source execution, grandchildren or signal-wide changes. The standalone worker imports only stdlib; no PYTHONPATH/site/customization discovery. Linux24/Python3.12 is the initially supported supervised transport platform; unsupported process/pipe supervision blocks before networking. Parent and worker communicate only over private stdin/stdout pipes using bounded length-prefixed UTF8 JSON frames; no pickle, arbitrary object deserialization or code. All frame types/keys/IDs strictly validated. The parent supplies the already authorized token only in private pipe memory, never argv/env/process title/errors/output, and does not read credentials itself. Exactly one serial allowlisted GET can be outstanding. Worker independently validates operation/IDs and constructs the fixed URL/headers, disables ambient proxies, uses verified TLS and rejects redirects. Worker processes raw HTTP/JSON under byte/shape limits and returns only safe builtin data/fixed errors; response URLs never become future operations.

Parent owns all counters/deadlines and uses nonblocking pipe IO with selectors, including partial frames, not blocking recv after a readability poll. Reject unsolicited, duplicate or request-ID/operation-mismatched worker messages. Local wire fixtures use only test-side patching of the worker/bootstrap; no production host/URL/TLS-disable/test-mode flag. Parent enforces monotonic absolute10second request and120second collection deadlines outside the blocking network worker, starting the request deadline before worker processing; spawn/IPC/response processing/close count toward the total. This bounds DNS/connect/TLS/headers/body/close even if a worker's socket timeout is idle-only. On request timeout, cancellation, worker exception or unexpected IPC/exit, parent stops all further requests, closes IPC, terminates then kills if needed, reaps and proves worker terminal before returning a blocked receipt. Termination/pipe cleanup has a separate maximum5second budget, included in a maximum125second end-to-end bound for a completed receipt; failure to confirm cleanup within that budget is fatal and emits no completed receipt. Close failure is not success. No abandoned thread, extra worker, retry or surviving authenticated socket may outlive an emitted receipt. If terminal state cannot be established, return no completed receipt and expose a fixed execution failure to the diagnostic runner; it must fail rather than imply cleanup. The concrete worker lifecycle and real stdlib wire behavior require implementation review and tests; a caller boolean/callback cannot claim deadline support. Fake clients remain synthetic.

## Input and result contracts

`MetadataRequest(source: SourceIdentity, source_ref: str)` uses exact expected source SHA/tree and a fixed source branch grammar: `refs/heads/feat/rc-pretag-metadata-1dfe` for same-source engineering observations, or `refs/heads/release/full-rc-candidate-[A-Za-z0-9][A-Za-z0-9._-]{0,79}`. No API host, repo, workflow, PR or run-ID override. Engineering observations are explicitly not version-selected final candidates. Reject `..`, trailing dot/slash, empty components and control/percent characters before networking. Invalid expectations fail before networking. The library reads no shell/Git command, local file or environment; the later diagnostic runner alone reads fixed GitHub environment fields and source identity. The worker only performs approved network operations.

`MetadataReceipt` carries schema `rc-pretag-metadata-v1`, source expectation, timestamps, request/byte counters, collection status (`observed_complete`, `partial`, `blocked`), endpoint observation statuses/codes, optional source/workflow/run/job/PR facts, passA/passB sanitized digest summaries, and the ordered full gate inventory. A typed `revalidation_observations` summary tuple preserves pass-B key/state/reason/count/full comparison digest without retaining a second copy of records. Preserve pass-A observations unchanged. Any difference adds a distinct `collection/snapshot_changed` row and blocked status; neither pass’s concrete failure reason is overwritten. Observed-complete requires equal ordered normalized A/B summary identities and a complete second-pass key set. All output still fits the unchanged256KiB receipt bound or is rejected. It has mandatory fixed `evidence_authentication=unverified`, `eligibility_status=blocked`, reason `authenticating_producer_unimplemented`, `artifact_bytes_verified=false`, `finalized=false`, both approvals false, `snapshot_atomic=false`, `principal_permissions=unproven`. `observed_complete` concerns metadata collection only and cannot clear a release gate. Failed/missing FINAL is an ordinary truthful result.

The exact ordered `policy_gates` tuple preserves all GATE_IDS under the global fixed `eligibility_status=blocked` and `blocker=authenticating_producer_unimplemented`; it does not contain per-gate success rows. Metadata-specific failures remain in separate observations, not fake implementations of old gate producers. Uncollected byte/security/tag/Release/version/review-authority gates remain explicitly unobserved. Existing policy serialization is not changed.

A receipt records `channel=fixed_origin_tls_bearer_request` only when the real adapter confirms that transport path. This is not independent token identity/capability proof. Public endpoints can return200 without permission, and a saved JSON object is not cryptographic provenance. Fake-client fixture output is marked `synthetic`; callers cannot set a true authenticated/approved flag. No authentication factory is added.

## Allowlisted GET operations

All routes are built internally under `https://api.github.com/repos/Eswink/coding-tools-mcp`, never from a response URL. No arbitrary suffix getter is exported. API version is pinned to the existing reviewed2022-11-28 version; live response compatibility remains unverified until separately approved operational evidence.

- Repository: empty suffix, not a trailing-slash redirect
- Source: `/git/ref/heads/{validated branch}`, `/git/commits/{expected SHA}`; verify exact ref string, object.type=commit, object.sha=expected SHA, commit response.sha=expected SHA and commit.tree.sha=expected tree
- Tree traversal: `/git/trees/{authenticated tree SHA}` without recursive=1; exactly root -> `.github` -> `workflows`, max3 tree nodes; every requested tree response.sha must equal its requested/parent-linked SHA and each parent-child path/mode/type/SHA must match; require truncated=false, unique component names, ordinary tree modes040000 and workflow blob mode100644
- Workflows: `/actions/workflows/dot-rc-integration.yml` and `/actions/workflows/final-rc-packages.yml`; pretag workflow presence is observed in the source tree without pretending an Actions run exists
- Runs: `/actions/workflows/{validated workflow ID}/runs?head_sha={expected SHA}&per_page=100&page=N`; `/actions/runs/{selected ID}`
- Jobs: `/actions/runs/{selected ID}/attempts/{current attempt}/jobs?per_page=100&page=N`
- Review scope: `/pulls/36`, `/pulls/36/reviews?per_page=100&page=N`, `/pulls/36/commits?per_page=100&page=N`; individual review rereads are not required because the complete list is reread

No `/artifacts`, `/zip`, `/logs`, `/releases`, tag-ref endpoint, collaborator/permission probe, GraphQL, external host or mutating method is allowed. HTTP redirects are rejected without retaining Location. Default TLS verification is mandatory; do not use ambient proxy settings. No retry/backoff/auth fallback. Token syntax receives only header-safety/bound validation, not a vendor-format regex or logging. Errors, including HTTPError body/reason and token-bearing Request repr, are replaced with fixed codes.

## Normalization and completeness

The old exact-dataclass codec is used only for the final receipt, never raw API JSON. The new API adapter owns a separate bounded object/array parser with the stated1MiB/1000item envelope limits, keys<=512 and wire/IPC value strings<=65536; retained identity/text stays512 or stricter, token<=4096 and rejects duplicate keys/nonfinite/deep input before operation-specific normalization. Preserve only needed identity/state primitives. Duplicate keys/nonfinite/oversized integers/invalid UTF8/depth/shape fail before normalization. No response object URL, body text, commit author/email/message, runner label or step/log text reaches output. For tree records retain only fixed searched names/mode/type/SHA after complete bounded tree validation. Opaque unexpected fields are ignored after shape/bounds validation, never treated as authority.

Counted Actions protocol: at most10 locally generated pages,100items each, invariant strict integer total_count, distinct positive IDs, no count overflow, exact terminal total, full nonterminal pages. For filtered run search require total_count and returned length strictly below1000. Retain all statuses. The selected newest is the maximal validated `run_number`; reject duplicate run_number across distinct IDs or disagreement with created_at ordering. Do not select a lower source run when the newest has unsupported event/path/repository or incomplete identity. Equal timestamp does not override run_number. Older runs remain inventory hashes; only the newest run gets jobs.

Run path must be the exact fixed workflow path; unsupported `path@ref` forms are conservatively blocked rather than stripped or normalized speculatively. Run times are optional where lifecycle state permits: queued need not have started_at; completed requires a consistent terminal timestamp/conclusion. Unknown status/conclusion records a bounded unknown code. Complete success metadata uses the same source/attempt/job invariants as the old helper. FINAL current attempt2+ is observed and explicitly unsupported, not silently changed to1. Jobs must explicitly carry source/run/attempt; request URL alone is not proof. Job name text is allowed only if in expected names; unexpected names contribute a digest/count and fixed blocker, not arbitrary text output.

Bare-array protocol: reviews keyed by review ID; commits keyed by SHA. Validate Link only as bounded same-route page relations: origin/repository/path/query exactly match the internally expected canonical page, unique relations, no alternate filters; never visit it. Generate next page locally. Require a short terminal page with no next relation, and independently repeat the complete inventory. If a full page has no Link and no earlier advertised last bounds it, continue locally numbered pages within the cap until a short terminal page; an empty next page is also valid terminal evidence. Cross-relation contradictions (including next>last), changed advertised last bounds, or a premature short terminal page before an earlier advertised last block. One extra locally generated empty probe after a full advertised-last page is allowed; it cannot contain data or a next link. Counted endpoints bind any last relation to ceil(total_count/100). Contradictory Link/pagination, cap exhaustion or duplicate identities blocks. Reviews at1000 block; PR metadata commits count and list must agree and remain <250, even when a short third page looks terminal. No permission claims follow from completeness.

Review rows retain numeric reviewer/review IDs, state, submitted_at and commit_id. Keep every bounded review record; do not collapse to latest-per-user approval. Stale/dismissed/changes_requested/pending/unknown remain explicit. PR head/base repository IDs must be fixed; merged=false means merge_commit_sha is only a proposed value, never a completed merge. Neither matching SHA nor author_association grants exact-tree independent approval.

## Revalidation and failure receipts

PassA observes source/ref/repository, fixed trees/workflows, complete run inventories/direct current runs/jobs and PR36/reviews/commits. PassB repeats mutable sets and binding reads; immutable commit/tree digests may be reread within remaining budget. Compare normalized full inventories including IDs/attempts/status/conclusion and PR counts/head/base/merged/review states. A changed state yields blocked/snapshot_changed. No silent retries until equal. All calls share128-request/16MiB/120s budget; the supervisor enforces absolute deadlines and requires worker termination as specified above; reserve budget for passB or mark revalidation unavailable. Two reads are not atomic or proof against undetected ABA changes.

If a prerequisite fails, skip its dependent reads with `prerequisite_unavailable`; continue independent bounded observations while budget permits. Never substitute an empty successful inventory for denied/missing visibility. A404 is `not_found_or_not_visible`, not an absence claim. Current source mismatch remains distinct from denied visibility. Run/job failures stay facts; authentication/byte/security completeness stays blocked.

For equality, compute a pass-independent `comparison_sha256` over domain `rc-pretag-metadata-v1/compare/<operation>` plus deterministic canonical sanitized records sorted by validated stable identity (numeric run/job/review ID; commit SHA; fixed tree path), including counts, completeness/visibility/status state and every compared identity/state field. Unknown status/conclusion/job-name strings retain a fixed code plus domain-separated hash of the bounded original field, so differing unknown values cannot normalize to equality; raw text never enters the receipt. Full review records retain their submission time/state even when sorted by ID. Bounded canonical whole-inventory comparison includes every sanitized record, including interior records beyond128; changed ordering alone cannot hide a changed record and count/hash mismatch blocks. Equal passes also emit a revalidation digest over the ordered second-pass key/state/comparison-digest summaries in the same compare/revalidation domain. No separate pass-domain envelope hash is emitted. Exclude token, raw headers/body and arbitrary URLs. Receipts are bounded by existing MAX_JSON_BYTES and per-list metadata records limited to128 where old strict codec imposes that limit; larger complete inventories retain deterministic bounded canonical sanitized hashes/counts, not silently dropped records. Selected jobs remain bounded by expected7/13; review detail retention is capped128, exceeding that bound blocks rather than summarizing a potentially relevant approval. No file output or finalization is done by this library. The later diagnostic entry handles only its explicitly bounded sanitized receipt file and source/run identity records.

## Risks and rollback

Semantic promotion is the main risk: callers may confuse a TLS metadata observation with authenticated final release evidence. Distinct schema, immutable false flags, no existing API upgrade and explicit absent fields prevent that promotion in this slice. Graph has dynamic dispatch/type-flow limitations; exact source review and negative boundary tests are mandatory. Keep1627 existing blobs/modes unchanged and permit only the exact pinned historical scope-test correction. Rollback is leaving the branch unintegrated or reverting precisely the16 additions and one correction, never tags/assets/durable authority. No runtime/security improvement is claimed.
