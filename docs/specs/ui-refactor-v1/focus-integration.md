# Approval focus integration

Round15 integration review found that the existing standalone production-component browser harness explicitly maps four source modules. A new cross-module import would be unresolved there and absent from its strict four-source manifest. Rather than introducing a reusable abstraction with one consumer and expanding unrelated release contracts, colocate the pure DOM helper inside ChatAuthorizationHost. Tests extract and execute that exact TypeScript function from the real component. The existing compiler, browser fixture and release hash already cover the full component, so no import is mocked away and no provenance gate is weakened. Remove the now-unneeded one-consumer helper file. All old host functions remain unchanged; the only new behavior is keyboard containment. The real application and standalone component suites must both pass the next candidate.
