# 需求文档：聊天授权v1

## 功能概述
为 Coding Tools MCP 增加 OAuth 身份、ChatGPT 对话关联和本机审批组成的三层权限边界。新的网络业务请求默认拒绝；获准聊天只访问其工作区和会话运行域。基准远端提交 22dbbecd3fbebef58b8b6bdca05e2f7080e0b128；本地离线源码 cc8f730，修改前逐文件核对远端 blob，不改无关文件。

## 历史经验与坑（来自记忆库）
暂无可用 Memory 服务。现有源码要求 MCP/Actions 复用 tools::call_tool；异步任务必须复用幂等和持久化实现。旧 OAuth 只有 bool 验证、30 天令牌及 mcp scope，无 sub；业务上下文当前共享。

## 术语定义
- Principal：验证签名、issuer、audience、有效期、scope 后的服务器账户。当前产品只有一个桌面所有者，不伪装成多用户身份提供商。
- ChatBinding：服务器 HMAC 生成的 OAuth issuer/sub/client 与 host conversation、工作区配置 ID 的绑定。
- ChatGrant：仅本机 IPC 能批准、可撤销、有绝对期限和空闲期限的授权。
- Remote：任何网络入口，包括 loopback 上经 FRP 转发的请求；不根据 IP 或用户参数自动豁免。

## 范围边界
In Scope：MCP 统一闸门、OAuth principal、审批/撤销/独占、scopes、会话运行域、桌面操作面板、负向回归、原有本地 API 回归。
Out of Scope：聊天窗口的工具发现和网络请求尝试无法由 MCP 服务端阻止；本方案阻止业务执行。授权后同工作区文件是共享资源，不是 OS 沙箱；有 exec 权限的代码不能被宣称为恶意租户隔离。没有可信会话元数据的旧 GPT Actions 不允许业务访问。公网 OpenAI mTLS 部署/真实 ChatGPT 双窗口验证列为发布验收，不由合成元数据测试冒充。

## 需求列表
### FR-1: 每个网络业务请求默认拒绝并验证 OAuth 身份
**优先级:** Must
**用户故事:** 作为桌面所有者，我要禁止未批准聊天读写或执行工具。
#### 验收标准（EARS）
1. WHEN 身份或会话字段缺失、类型错误、过长 THEN 系统 SHALL 拒绝并不创建业务状态。
2. WHEN token 的签名、issuer、audience、expiry、nbf 或 mcp scope 错误 THEN 系统 SHALL 返回认证失败。
3. WHEN danger permission 或模型提供授权布尔/身份字段 THEN 系统 SHALL 不得绕过 ChatGrant。

### FR-2: 本机审批并实施有限生命周期
**优先级:** Must
**用户故事:** 作为操作者，我要在桌面审批当前聊天，而非将主密钥交给模型。
#### 验收标准（EARS）
1. WHEN 当前未批准聊天调用 request_chat_authorization THEN 系统 SHALL 只创建有界、90秒有效的去重请求。
2. WHEN 本机批准 THEN 系统 SHALL 绑定工作区、账户、对话、权限；授权上限8小时、空闲30分钟。
3. WHEN 撤销、空闲过期、绝对过期或应用重启 THEN 系统 SHALL 拒绝后续请求；重启不恢复活跃授权。
4. WHEN 开启独占并批准新会话 THEN 系统 SHALL 原子撤销同一工作区其余授权，不影响其他工作区。

### FR-3: 会话运行状态隔离
**优先级:** Must
**用户故事:** 作为操作者，我要避免不同聊天操作彼此任务、进程和归档。
#### 验收标准（EARS）
1. WHEN A和B均获准 THEN 系统 SHALL 分离 cwd、进程会话、异步幂等表、任务查询、harness与history目录。
2. WHEN B提供A的job_id/session_id/history参数 THEN 系统 SHALL 拒绝或返回当前域未找到，不披露A结果。
3. WHEN 后台任务开始执行 THEN 系统 SHALL 再次检查授权；撤销不承诺回滚已产生副作用。
4. WHEN 桌面操作者查看或取消任务 THEN 系统 SHALL 保留可信本地控制入口。

### FR-4: 工具能力范围与不可自提权
**优先级:** Must
**用户故事:** 作为操作者，我要批准只读或开发能力，而非任意管理权限。
#### 验收标准（EARS）
1. WHEN 工具调用 THEN 系统 SHALL 在统一入口检查工具到scope的显式映射；未知工具不自动获准。
2. WHEN 仅只读授权尝试执行/patch/harness写/history写 THEN 系统 SHALL 拒绝。
3. WHEN auth_status 或申请接口调用 THEN 系统 SHALL 不返回其他会话、工作区路径、原始token/session/subject。

### FR-5: 桌面可用、可观察与安全退化
**优先级:** Must
**用户故事:** 作为操作者，我要看见待批准和有效授权并撤销。
#### 验收标准（EARS）
1. WHEN 用户打开工作区 THEN 系统 SHALL 提供审批、拒绝、撤销全部、独占设置和会话指纹对照。
2. WHEN 服务不支持会话身份 THEN 系统 SHALL 显示不可用，而非降级成全局解锁。
3. WHEN OAuth授权失败 THEN 系统 SHALL 提供标准WWW-Authenticate发现信息；固定callback与resource校验不依赖不可信Host。

### FR-6: 可复核交付
**优先级:** Must
**用户故事:** 作为维护者，我要能区分实现、测试与公网验证。
#### 验收标准（EARS）
1. WHEN 提交候选 THEN 系统 SHALL 提供真实差异、负向测试、构建/检查退出码及限制记录。
2. WHEN 无真实公网或双平台证据 THEN 系统 SHALL 不标记对应验收通过、不覆盖正式Release。

## 非功能需求
### NFR-1: 有界与敏感信息最小化
每工作区授权请求和运行域有界，重复申请不弹窗轰炸；认证失败不进入业务日志。HMAC绑定不向模型暴露原始ID，审批不经MCP。状态锁不跨耗时工具执行持有。

## 依赖关系
依赖现有 OAuthRuntime、统一 tools::call_tool、Tauri 可信本机 IPC、SessionStore、ExecTaskStore 和 Harness；不新增第三方认证依赖。远程真实窗口隔离的部署验收依赖可信 ChatGPT 请求入口（例如验证 OpenAI mTLS 的反向代理）及真实双窗口负向验证。配置缺失不得自动降低授权要求。
