# 聊天授权评审 v17：Windows 测试宿主控制台创建方式

## 对照证据

v15 的 Windows debug 作业 `102765803750` 在 Git Bash 构建步骤中，中等令牌 USER32 真实窗口冒烟成功；后续 PowerShell + Tee-Object 中启动 Python 宿主却返回 `0xc0000142`。安装包作业 `102765669778` 的安装载荷摘要核验成功，原生测试同样 0/8，未生成宿主自身的应用输出/退出记录。现有证据不支持把此错误直接归因为产品审批代码或 WebView2 版本不匹配。

## 单一待验证假设

不同宿主控制台场景参与了限制令牌下的控制台初始化失败。本候选仅把 Windows 测试启动器的 CREATE_NO_WINDOW 换成 DETACHED_PROCESS；保留 CREATE_SUSPENDED、CREATE_NEW_PROCESS_GROUP、CREATE_UNICODE_ENVIRONMENT、中等完整性/非提升令牌核验和私有 kill-on-close Job。DETACHED_PROCESS 仅与控制台分离，不代表测试可以后台失管运行。没有修改产品 Rust、令牌策略、DACL、注册表或 WebView2 沙箱。

微软文档区分了 CREATE_NO_WINDOW 与 DETACHED_PROCESS 的控制台行为；文档并没有证明本仓库错误的唯一根因，必须实跑验证：
https://learn.microsoft.com/en-us/windows/win32/procthread/process-creation-flags

两个实际失败的 PowerShell 入口均在业务测试前增加同场景降权窗口探针。探针使用相同 launch 函数，最多等待 15 秒，保留精确退出码和非提升令牌证据，失败后不得继续业务验收；不自动回退到管理员/禁用沙箱。
