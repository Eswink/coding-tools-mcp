## 认证补强
- 对授权请求和令牌交换要求显式、精确匹配已公布的 OAuth resource；授权码保存该资源，跨 origin、替换、遗漏或尾斜杠差异均不能兑付。
- issuer 与 aud 仍绑定同一可信 PublicOrigin，不从请求 Host 或模型参数信任身份。
- PKCE S256 challenge 验证为规范的 32 字节无填充 base64url；client_id 上限 256 字节。
- 已签名 token 只接受单一 mcp scope，拒绝附带未知 scope、重复 scope 或空 jti。
- 授权登录页面不接收工作区路径展示；已有 MCP/Actions 调用本来传 None，本项为未来调用者的防泄露加固，不声称发现现行初始化泄露。

## 回归与边界
新增 7 项 Rust 回归覆盖 resource/PKCE 输入、scope 扩展、路径 canary、正确交换、授权码重放、资源遗漏或替换、origin 改变、过期授权码和错误 verifier。测试参数、令牌和 principal 均为合成夹具；不包含真实用户密钥，不冒充真实 ChatGPT 窗口验收。

参考：OpenAI 官方认证文档要求 ChatGPT 在授权和 token 请求携带 metadata.resource，并要求服务端验证 audience 与 scope：https://developers.openai.com/plugins/build/auth 。对话元数据仅作关联，OAuth 证明用户而非该元数据的 OpenAI 来源；可信公网入口与真实双窗口验证仍属于发布门禁。
