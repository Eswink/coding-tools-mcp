# 聊天授权候选自审 v1

基线：远端 `22dbbecd3fbebef58b8b6bdca05e2f7080e0b128`，仅候选分支。不修改 main、版本号或正式 Release。

## 已实施
OAuth principal（本机单一 owner，非 openai/subject）、固定回调、issuer/resource/audience/时效/mcp scope、登录限流；HMAC 绑定 profile/root/issuer/subject/client/conversation；默认拒绝统一闸门；本机审批、撤销、独占、pending/idle/absolute TTL；每聊天 cwd/session/job/harness/history 运行域；无可信上下文的旧 Actions 拒绝；本机跨运行域取消任务。

## 自审发现及修正
- 原 OAuth 仅返回 bool 且旧 token 没有 sub/client_id。改为不可由参数构造的已验证 principal；旧 token 需重新连接。
- 原启动提示词强制每个聊天立即 bootstrap。改为用户明确申请、本机批准之后才初始化，未批准不写归档。
- 不能只保护任务提交；list/get/cancel、stdin/process、history/harness/cwd 同样隔离。
- scope 升级不能通过重复申请完成；必须撤销后申请，桌面审批仅能取请求权限的子集。
- 前端 effect 首次轮询读取 busy 会触发错误依赖。已使用 untrack，并以工作区 generation 和 mutation 版本丢弃旧响应。
- 原 noauth HTTP 回归不是新安全模型的正向用例。改用测试专用真实签名令牌+服务端审批夹具，仍保留断线与同端口重启的实际命令/幂等断言；新增 noauth 拒绝和 Actions 拒绝回归。

## 发布阻断与边界
- 真实 ChatGPT 双聊天 + 可信入口（例如验证 OpenAI mTLS 证书链/用途/SAN）尚未验收。openai/session 本身不带独立签名，持有 OAuth token 并能伪造宿主元数据的客户端不属于已证明隔离范围。元数据不应当作密码或用户身份。
- 此实现拒绝未授权业务执行；不能禁止 ChatGPT 进行工具发现或发起被拒绝的请求。
- 物理工作区文件仍共享，文件读取/exec 不是恶意租户沙箱。授权 exec 的用户代码可能产生其他副作用，撤销不回滚已发生操作；后台任务启动前重检、后续 RPC 拒绝，已运行任务由本机取消。
- 授权进程内保留；应用重启全部失效。会话绑定依赖稳定签名密钥与 profile/root/origin；更改绑定参数不会自动转移旧历史/任务。
- 每工作区最多64授权记录/64运行域、全局1024授权记录。运行域不自动回收仍有状态的进程；到限拒绝，操作者先停止任务再重启。新模式拒绝 Bearer/noauth 网络业务及旧 Actions，属于有意的兼容性变更。
- OAuth 仅 authorization-code + S256 PKCE，8小时令牌、无 refresh_token；不宣称实现完整身份提供方所有扩展。
