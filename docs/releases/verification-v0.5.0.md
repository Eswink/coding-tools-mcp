# v0.5.0 UI review candidate — Windows / Ubuntu

**状态：UI 评审候选，不是已公开 Release。用户视觉确认前不得合并或发布。**

本版在 v0.4.0 的独占会话、OAuth/Refresh Token、任务排空与密钥模型之上重构界面。版本号单独递增用于识别候选安装包，禁止用新界面覆盖原 v0.4.0 的同名附件。候选源码以工件内 source/tree/run 标识为准；此文档不是测试通过证据。

## 界面范围

五个页面保留原 URL：工作区、通用设置、共享密钥、FRP 配置、软件管理。统一深蓝侧栏、浅色/深色主题、语义颜色、组件布局与键盘操作。参考图中的模拟时间、运行状态、额外软件版本及未实现设置不会伪装为真实能力。

服务/子面板切换读取各表单的未保存与处理中状态。保存完成或修改恢复原值后不再无端提示离开；未保存草稿仍须确认，保存中的操作仍不能被页面切换越过。审批框仍要求本机指纹确认和非空权限子集；焦点循环不自动批准。

## 安装与回退

Windows x64 使用 NSIS；安装前退出旧程序并备份配置及对应系统账户的密钥恢复材料。包尚未商业签名，可能显示未知发布者。不要上传密码、Client Secret、Refresh Token 或未经脱敏的配置。

Ubuntu 22.04/24.04 amd64 优先 DEB，在已登录的普通桌面用户、D-Bus、可用且解锁的 Secret Service 环境下运行，不要 sudo 启动 GUI。AppImage 的自动验收范围为 extract-and-run；不能外推所有 FUSE、Wayland、ARM、无桌面 Server 或 GPU 环境。

不需要删除工作区或历史文件来应用新 UI。加密配置不能单独跨系统用户恢复。密钥缺失、存储损坏或未结束任务状态不明时应停止并诊断，不能覆盖原数据或强行解除排空栅栏。回退使用保留的 v0.4.0 程序和兼容配置备份；停止候选后重新启动必需重新本机批准，不自动重放任务。

## 候选核验

源码回归必须覆盖官方完整前端驱动、Svelte/type/build、Windows/Ubuntu Rust，以及实际构建的路由截图。浏览器截图中的 IPC 为明确标注的合成夹具，只用于布局与交互；不能冒充原生桌面或真实 OAuth。

新版原生候选还必须完成 Windows NSIS 与 Ubuntu 两系统、两种包共五种组合。每组要求五页面 × 两种主题 × 两种窗口尺寸的 20 张实际原生截图，再继续完整十二阶段本地 OAuth、指纹审批、100 次外会话静默拒绝、刷新、排空、真实 90 秒到期、重启与重放拒绝验收。新 UI 截图不得替代安全验收，旧 UI 的安全验收也不得替代新 UI 截图。

所有原生测试用独立临时工作区、明确标记的合成凭据与会话 metadata；不使用用户真实账号，不关闭沙箱。截图记录原生窗口请求尺寸和实际 CSS viewport，不能在高 DPI 系统中混为一谈。安装载荷与源提交、版本、运行 ID、文件摘要必须一致。

## 发布边界

真实 ChatGPT 账号的会话 metadata 与长期自动刷新、操作系统通知横幅显示、未覆盖的硬件与图形环境仍需独立核验。历史 Windows 偶发无输出超时的唯一根因不因 UI 回归通过而变成已确认。

本候选不包含独立 Draft PR #11 的公网 OAuth 路由诊断与 Nginx 修改。不变更生产 Nginx，不重新发布旧版本，不把参考图里的绿色状态写成实际健康结论。

用户确认最终画廊后，才进入独立合并/发布流程；必须从最终提交重跑相应门禁，不能直接将失败或过期运行中的包提升为 Release。
