## 安装与升级

本版提供 Ubuntu 22.04/24.04 amd64 DEB、AppImage 和 Windows x64 NSIS，沿用现有图形桌面界面。下载后先核对同一 Release 的 SHA256SUMS，退出旧程序，再安装。保留升级前应用配置和对应操作系统用户凭据的离线备份；不要把配置、OAuth token、主密钥或日志中的秘密发到聊天或公开仓库。仅复制加密配置文件不能替代系统凭据备份。降级应恢复升级前备份，不要让旧版改写新版状态。

Ubuntu：`sudo apt install ./MCP_0.3.0_amd64.deb`，随后从应用菜单启动；AppImage 先 `chmod +x MCP_0.3.0_amd64.AppImage` 后以普通用户执行。CI 的 AppImage 使用 extract-and-run 模式，不能把它当作所有机器 FUSE/Wayland/GPU 都通过。

Windows：运行 `MCP_0.3.0_x64-setup.exe`，正常用户启动应用；未商业签名可能提示未知发布者。不要为测试关闭 Defender、WebView2 沙箱或系统访问控制。Release 标为“待本地核验”的 Windows 版只通过已列出的基本安装和窗口检查，不能声称完整审批已过 CI。

## 授权的正常流程

先在本机桌面配置工作区和公网 HTTPS 入口，再在 ChatGPT 连接 MCP 并完成 OAuth。已有连接可能需要重新登录。每个新聊天默认没有业务授权；在目标聊天明确要求调用 `request_chat_authorization`，仅申请需要的工作区和权限，随后到该工作区的桌面聊天授权面板核对请求、权限和会话指纹并批准。不要在聊天中提供长期主密钥，也不要批准无法对应到自己操作的请求。

OAuth 身份与聊天批准是两层检查：只登录 OAuth 不等于所有聊天都可以执行。聊天会话标识用于区分上下文，不是密码或不可伪造的身份凭据。默认空闲 30 分钟、绝对 8 小时；批准不跨应用重启恢复。桌面可拒绝、撤销全部和启用独占模式。

## 本地验收记录（每项记录实际结果，不预填通过）

| 场景 | 预期 | 实测 |
|---|---|---|
| 同一账号新聊天 A/B，尚未桌面审批 | 两者业务读取/执行均拒绝，只允许授权状态和申请入口 | 待核验 |
| 在桌面批准 A，不批准 B | A 在批准范围内工作；B 仍拒绝 | 待核验 |
| 在 B 知道 A 的任务/会话 ID 后尝试读取、取消 | B 无法读取或取消 A 的资源 | 待核验 |
| A 只读批准后请求写文件、执行命令、自提权 | 超出权限拒绝；模型不能自行批准 | 待核验 |
| 撤销 A 或撤销全部 | 后续业务调用立即拒绝；不将正在运行的任务自动回滚当作保证 | 待核验 |
| 独占模式切换至 B | A 失去后续访问，B 仅在其授权范围可用 | 待核验 |
| 重启桌面程序 | OAuth 凭据按原机制保留；A/B 都必须重新获批 | 待核验 |
| 缺失/冲突会话元数据，OAuth失效或错误资源 | 默认拒绝，不退化成匿名或共享主密钥访问 | 待核验 |

真实 ChatGPT 双窗口及公网请求来源未由合成 CI 元数据证明；应使用本表完成最终客户端验收。失败时保留版本、步骤、非秘密错误码和脱敏结果，立即撤销授权；不要公开令牌、主密钥、原始配置或个人文件内容。

## 能力与信任边界

本版针对 OAuth 身份 + workspace + host conversation metadata + server grant 实施业务入口及任务归属校验。持有有效 OAuth token 的恶意客户端可能自行构造会话元数据，不能把该标识描述成经过密码学认证的 ChatGPT 来源。需要可信宿主元数据；`exec.run` 是代码执行授权，不是操作系统沙箱，多聊天在同一工作区仍共享真实文件。撤销禁止后续请求，但不保证终止已发出的所有子进程。旧 Actions 业务入口没有合格会话上下文时拒绝，不作为绕过通道。

所有发布为 prerelease；严格原生 CI 与“用户批准的 Windows 本地核验例外”分别标记。例外不豁免双平台 Rust/HTTP 隔离、编译、前端、Ubuntu 四组合原生安装、Windows 包字节与基本窗口检查。旧稳定候选 Release 不覆盖。
